# Security

## Reporting a vulnerability

Open a GitHub issue for anything non-sensitive. For a vulnerability that should
not be public first, use GitHub's **private vulnerability reporting** on this
repository (Security → Report a vulnerability).

Please include what you tried, what happened, and what you expected. A proof of
concept against `tests/fixtures/` is ideal — those fixtures are generated by
`scripts/make_fixtures.py`, so a new attack can be added as a fixture function
and becomes a permanent regression test.

## What this project takes seriously

The full analysis is in [docs/THREAT_MODEL.md](docs/THREAT_MODEL.md), including
an explicit list of what is **not** defended against. The short version:

**A contract is untrusted input.** The counterparty wrote it, has a financial
interest in how it is assessed, and controls every byte. Document text therefore
never enters the system prompt, is fenced with a per-request nonce, and cannot
produce a user-visible statement without passing a verification gate that reads
only document passages.

**Nothing is shown that has not been checked.** Every statement cites spans;
every span is re-resolved against a hash of the text it covered; every claim is
judged against only its own evidence. Failures are removed and reported, not
annotated.

**The user's document is the most sensitive thing here.** It is never written to
disk. PII is pseudonymised before any model call. Logs are scrubbed by a
processor. The whole system runs with no network egress at all.

## Security controls in CI

Every push runs:

| Check | What it catches |
| --- | --- |
| `bandit` | Known-dangerous patterns in source |
| `pip-audit --strict` | Dependencies with published vulnerabilities |
| `scripts/verify_defences.py` | A regression that would let a poisoned document through |
| Credential scan | Anything shaped like a live API key in the tree |
| Control-character scan | Literal bidirectional or zero-width characters in source (Trojan Source) |
| Full test suite | Including `tests/security/`, run with no API key |

## Reporting a false positive

A detector that flags ordinary contract language is a real bug, not a minor one:
a security control people learn to ignore is worse than no control. The benign
corpus in `tests/security/test_injection.py` exists for exactly this, and a
clause that is wrongly flagged belongs in it.

## Supported versions

This is a hackathon project and only `main` is supported.
